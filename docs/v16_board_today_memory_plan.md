## 1. 今日快照 `memory/today.json`

必填键：`date`、`fetched_at`、`agenda`、`tasks`、`summary`、`summary_at`、`doc_url`。

- `date`：东八区 `YYYY-MM-DD`
- `agenda` / `tasks`：与现在看板接口相同 `{ok, items}` 或 `{ok:false, error, items:[]}`
- `summary` / `summary_at` / `doc_url`：未生成时为空字符串
- 文件损坏或缺键：失败，提示删掉该文件后点刷新。不静默当空、不套默认

加载规则：

1. 未点刷新，且文件日期等于今天 → 直接读文件
2. 无文件、日期不是今天、或点了刷新 → `lark-cli` 拉日程和待办并写回
3. 同一自然日刷新：只更新日程/待办和 `fetched_at`，已有总结保留
4. 换天：新快照，总结和文档链接清空

看板「今日」页：切走再切回不重拉；进程重启后读文件。按钮：刷新、让咕嘎讲、生成总结、写入飞书文档。展示缓存时间。

## 2. 总结

材料只来自当日快照 + 当天 `chat.jsonl`（`ts` 日期等于今天）。不调飞书工具。日程或待办 `ok` 不为真则拒绝生成，让用户先刷新或去飞书页。

调用现有 Agent 的 `llm.chat`（不带 tools），人设当 system，不注入对话历史、不走工具协议。用量按返回的 `usage` 记一行 `usage.jsonl`。

「写入飞书文档」：总结为空则失败（先生成）。仍走 `docs +create`，每次新建一篇，标题 `{date} 工作总结`，写成功后把 `doc_url` 记进快照并打开链接。

## 3. 记忆页

页签顺序：今日 / 对话 / 记忆 / 人设 / 模型 / 用量 / 飞书。

页上说明：咕嘎没有另一套记忆库；每次说话前把 `chat.jsonl` 最近 N 条灌进模型（N 在人设页改）。列出当前窗口里的那 N 条。`N=0` 时明确写不会喂对话。全部历史仍在「对话」页。
