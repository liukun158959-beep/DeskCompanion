# V26 实施计划：清日常自动扫仓，规划只读缓存

> 2026-08-30 grill-me。用户拍板：跟清日常走，不问刷什么时单独扫。
> 2026-08-30 晚真机验：本机 MAA 6.16.8 点小工具「开始识别」会**自己进仓库 / 干员箱**扫完全部，不需要人手先停在养成材料页。官方文档「小工具要人先进仓库」在本机不成立。
> 桌宠仍不把小工具当入口（人不点）。触发走「更新数据」写进任务队列 + 整段 `LinkStart`。
> 不链 MaaCore、不自己 OCR、不注入 Unity。

## 0. 问题

**When** 博士已经能对桌宠说清日常，接着要问今天刷什么  
**I want** 仓库材料由 MAA 进游戏扫出来，不要我打开小工具点识别  
**so I can** 规划读真实库存，缺仓失败可见，而不是手填 json 或截图猜图标

现在的凑合：森空岛没有仓库；桌宠点游戏被 ACE 拦；小工具本机能自动扫，但要人（或脚本）去点「开始识别」。新产品必须比「每晚点一次识别」更少打扰：跟已经在跑的清日常走。

## 0.5 鸟瞰：产品到哪了、本刀切哪一块

北极星仍是两件事：① 飞书今日安排 ② 托管长时间任务（第一例：本机 MAA 清日常）。「今天刷什么」是 ② 之上的下一层，不是第三件雇工。

| 层 | 状态 | 说明 |
|----|------|------|
| 今日安排 | 已落地 | 看板 / 气泡三壳（今日、方舟、对话）；会前打断、勾飞书待办完成、改日程仍不做 |
| 清日常 | 已落地 | 8 项勾选 + 开游戏 + 远控 `LinkStart-*`。本机已装 MAA 6.16.8（管理员、PC 官服）。V26 起下发改走整段 `LinkStart` |
| 扫仓进账本 | **本刀（V26）** | 清日常顺带让 MAA 扫仓库，写入 `arknights_account.json` 的 `inventory`。规划只读缓存 |
| 今天刷什么 | 规格冻、代码零（V25） | 策略表已冻。没有今天的仓就失败可见。本刀不写规划器 |
| 森空岛用户模型 | 接口已验、代码零 | 身份、实时理智、月卡、剿灭/保全额度、`chars[]`。没有材料仓库。本刀不写同步 |

仓库三条死路与一条活路：

| 通道 | 结论 |
|------|------|
| 森空岛 | 没有材料 / 龙门币 / 代理卡 |
| 桌宠点游戏仓库 | Unity/ACE 失焦不吃 `SendMessage`；非管理员光标不动。禁止 Hook/注入 |
| MAA 小工具「仓库识别 / 干员识别」 | **本机已验会自动进界面扫完**（需管理员；游戏不能最小化；缩放 100%、16:9）。游戏没就绪会任务出错。人不点，桌宠不当入口 |
| MAA「更新数据」+ 整段 `LinkStart` | **本刀入口**。UI 任务，会自动进仓库，结果写入 `{MAA目录}/data/DepotData.json` |

远控 `LinkStart-*` **没有**仓库 / 更新数据 type。现在清日常只下发这 8 项，**即使 GUI 勾了更新数据也不会跑**。要对齐「清日常顺带扫仓」，必须写队列再下发整段 `LinkStart`。

本机已有缓存（2026-08-30 用小工具点出来的，证明文件格式，不证明桌宠触发）：

- `data/DepotData.json`：`done=true`，约 88 件，`syncTime` 19:02:22。含养成材料 +「全部」里的源石 / 合成玉 / 龙门币 / 赤金 / 采购凭证。**仍无代理卡、理智药**
- `data/OperBoxData.json`：`done=true`，拥有 423，精二 141 / 精一 31 / 未精 251。**不当仓库**；干员进度优先森空岛（有技能 / 专精 / 模组）

本机 `gui.new.json` 已有 `UserDataUpdateTask`（`UpdateDepot=true`），间隔却是 `EveryTime`。本刀改成 **每天一次**。

## 1. 非目标

- 不问「今天刷什么」时现扫仓（远控没有单独更新数据 type；小工具能扫，但产品不要人点）
- 链 MaaCore / `:8848` / 桌宠点屏幕 / 注入
- 自己写仓库 OCR；把 OperBox 当库存账本
- 实现 V25 规划器、森空岛同步（本刀只把仓备好）
- 代理卡、理智药：MAA 扫不到。缺键失败，不当 0
- 自动改 MAA 关卡、库存保持刷图
- 会前打断、勾飞书待办

## 2. 决策

| 项 | 选择 |
|----|------|
| 何时扫 | 清日常这一趟。规划只读缓存 |
| 怎么触发 | 拉起 MAA 前写入任务队列：桌宠勾选的 IsEnable + 强制 `UserDataUpdate`（仓库开、间隔 Daily）；下发 **一条** `LinkStart`，不再只丢 `LinkStart-*` |
| 怎么读 | `maa_exe` 同级 `data/DepotData.json`。`done!=true`、没有 `data` 对象、或 `data` 为空对象 → 失败，不改账本日期 |
| 新鲜度 | `syncTime` 必须是**本机日历今天**（本地日）。缺时间戳或不是今天 → 失败，文案写先开一次清日常 |
| 写入 | 官方 itemId→中文名，写入 `arknights_account.json` 的 `inventory`（gitignore）。覆盖扫到的键，**不删**扫不到的键（代理卡、药仍手填） |
| 干员 | 不读 OperBox 进 inventory。交叉校验以后另开 |
| 肉鸽/生息 | 仍以桌宠勾选为准写进队列；默认不勾则 IsEnable=false，避免整段 LinkStart 误开 |

## 3. Must（≤3）

1. 清日常会让已连接的官方 MAA **自动进仓库扫一遍**（人不点小工具）。
2. 规划读 `DepotData.json`；无文件 / 未完成 / 不是今天 → 失败原文，不编库存。
3. 扫到的件按 itemId 翻译后进 `inventory`；代理卡、药不在结果里就不假装有。

工程怎么改见 `v26_maa_depot_inventory_tech.md`（§8 已拍板）。整体顺序与数据三层以主 PRD 为准：本刀只做账号状态里的仓。

## 4. 本刀要改的文件

- `maa_job._dispatch_maa`：写队列 + `LinkStart`；清日常结束后读仓（文件尚未出现则等，超时失败）
- `maa_maa_cfg`：补写 `UserDataUpdate`（Depot 开、间隔 Daily）；按桌宠勾选改各 `TaskType` 的 `IsEnable`
- 新建只读：`DepotData.json` → 中文 inventory（item 表用 MAA `resource` 或已有企鹅/item_table，禁止 LLM 猜 ID）
V25 规格不改策略表。本刀只保证问刷什么时「仓从哪来」。主 PRD 已对齐整体计划，实现时不要另写愿景文档。

## 5. 验收

- Given 游戏已开、MAA 由桌宠计划任务拉起，When 点开始清日常且至少勾了一项日常，Then MAA 日志出现 `Depot` / 更新数据，且 `{MAA}/data/DepotData.json` 的 `syncTime` 是今天。
- Given 刚清完日常，When 问今天刷什么（规划已实现时），Then 用缓存库存，不要求再点识别。
- Given 没有 `DepotData.json`、日期不是今天、或 `data` 为空，When 问今天刷什么，Then 失败，写明先开一次清日常，不出现「当 0」，不把空扫标成今天。
- Given 缓存有龙门币、没有代理卡键，When 规划要比代理卡，Then 代理卡通道失败样例，养成仍可读材料。
- Given 桌宠没勾肉鸽，When 清日常，Then 队列里肉鸽 `IsEnable=false`，MAA 不跑肉鸽。

## 6. 最危险假设

1. 本机 6.16.8 写完 `gui.new.json` 再计划任务拉起，会读到 `UserDataUpdate`。验证：桌宠清日常后（不是手点小工具）`DepotData.json` 的 `syncTime` 是否刷新。
2. 整段 `LinkStart` 不会忽略刚写入的 IsEnable。验证：只勾基建+更新数据时日志只有这两条链。
3. itemId 表与官服一致。验证：抽 3 个已知材料（卷1、D32、龙门币）数量和游戏对得上。
4. 清日常当时游戏未就绪（手点曾连挂）会扫仓失败。验证：失败必须可见；空 `data` 不得把 `depot_sync` 标成今天。
