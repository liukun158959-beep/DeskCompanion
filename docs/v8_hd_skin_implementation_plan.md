# V8 实施计划：咕嘎全动作 2× 高清源

> grill-me 对齐后冻结。2026-08-14。

## 0. 决策速查表

| 项 | 选择 |
|----|------|
| 清晰度 | 源帧从 192×208 提升到 384×416，逻辑显示尺寸不变 |
| 范围 | 原 8×9 精灵表、左右扒边、后颈拎起、落地全部统一 |
| 动作 | 帧数、顺序、姿态、锚点不变，只处理清晰度和边缘 |
| 边缘 | 清除旧精灵表绿色溢色，保留逐像素透明通道 |
| 拎起母版 | `guga-drag-lift-master.png` 同步替换为后颈拎起版，删除帽顶尖角版本 |

## 1. 资源规格

1. `spritesheet.webp`
   - 8×9 格，每格 384×416，总尺寸 3072×3744。
2. `cling-left.webp` / `cling-right.webp`
   - 5 帧，每格 384×416，总尺寸 1920×416。
3. `drag-lift.webp`
   - 5 帧，每格 384×416，总尺寸 1920×416。
4. `drag-land.webp`
   - 6 帧，每格 384×416，总尺寸 2304×416。
5. 全部使用无损 WebP RGBA。

## 2. 清晰化处理

1. 对旧表先按绿色通道差值去除绿边和绿色半透明溢色。
2. 使用 Lanczos 放大到 2×，再做克制的反锐化掩模；不重新生成姿态。
3. 新动作使用同一处理参数，保证线条锐度和透明边缘一致。
4. 不改变每帧不透明内容的相对位置，不重新排帧。

## 3. 加载器适配

1. `pet.json` 声明 `sourceCellWidth=384`、`sourceCellHeight=416`。
2. `skin.py` 按源帧尺寸切图，同时保留逻辑帧尺寸 192×208。
3. 内容包围盒从源坐标归一化到逻辑坐标，贴边计算不因高清源改变。
4. `pet.py` 当前动作包围盒同样归一化；1.0/1.5/2.0 分别渲染为 192×208、288×312、384×416。
5. 缺少源帧尺寸或尺寸不匹配时明确失败，不猜测、不回退。

## 4. 验收

1. 所有横条尺寸和帧数严格匹配。
2. 1.0 档显示尺寸不变；2.0 档直接使用高清源，不再放大低清帧。
3. 原 8×9 表每格不透明包围盒位置与处理前一致，动作不漂移。
4. 左右扒边、后颈抓点、落地脚底锚点保持不变。
5. 透明边缘无绿色描边，WebP 解码模式为 RGBA。

## 5. 不做

不重画原动作，不用生成式模型改 8×9 姿态，不增加新帧，不改变桌宠逻辑尺寸，不保留低清资源作为运行时 fallback。
