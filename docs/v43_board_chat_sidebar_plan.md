# V43：看板改为对话工作台（侧边栏 + 新 session）

> 2026-09-03。用户四点已明确。GitHub #18。未开工。

## 0. 问题

**When** 作者打开看板要跟凯尔希干活（问今日、带上某份技能、对着某个已连仓库说话、或下令开游戏/清日常）  
**I want** 看板本身就是对话工作台：能发消息、能开新线程、输入时能点选已有 skill / CLI / 仓 / 方舟动作；记忆人设技能不再跟「今日」平级抢顶栏  
**so I can** 不用在十个顶栏 tab 和头顶气泡之间找入口，也不用「清空对话」才能换话题

现状替代：对话页只读 `memory/chat.jsonl`（V12 规定不在看板里发消息，说话走气泡）；记忆 / 人设 / 技能 / 今日 / 方舟是平级 tab。新产品必须比「切 tab + 去气泡打字」更快。

## 1. 非目标

- 不实现。本文件只冻结需求。实现前再 grill-me 一次工程切法。
- 不另建工具总表 / 插件市场 / 任意 shell。chips 只指向已有 `skills/*/SKILL.md` 和已注册工具。
- 不新增 MAA 能力；方舟 chips 走现有开游戏 / 清日常 / 同步森空岛 / 今天刷什么。勾选仍是气泡、看板方舟页、右击、对话共用的那一份。
- 不把「清空对话」当成新 session。
- 不砍气泡：气泡继续说**当前** session。
- 不做云同步 session、多用户。
- 不开 V25 活动商店 / 企鹅、#8 UAC、#9 会前打断、#10 判断层。
- 不把清日常状态小窗搬进看板。

## 2. Must（≤3）

1. **看板能对话，且能开新 session。** 假设：作者会在看板里把一句话发完，而不是只当历史浏览器。新 session = 新线程，旧线程留在历史里可打开。气泡与看板共用当前 session。
2. **输入框能为本轮点选上下文 / 动作。** 假设：点选比纯自然语言更少漏调工具。可选范围仅：本库 skill、已注册且包装 CLI 的工具（`lark-cli` / `gh`，不是任意命令）、GitHub 看板同一套已列出仓库、已有方舟动作。
3. **信息架构：功能进侧边栏；记忆 / 历史 / 人设 / 技能是对话子界面。** 假设：顶栏平级 tab 是找入口慢的原因。侧边栏承载今日、对话、方舟、GitHub、飞书、日志、模型、用量。日志仍隐蔽标红，只是从页脚改到侧边栏，不当对话子页。

## 3. 拍板

| 项 | 选择 |
|----|------|
| 对话从哪发 | 看板对话主界面可输入、可发送，走现有 `send_chat` / Agent，失败原文与气泡同一套 |
| session | `chat.jsonl` 每条带 `session_id`；`user_state` 记当前 id。新对话生成新 id，不删旧文件 |
| 气泡 | 读写当前 session。切 session 后气泡历史跟着换 |
| skill chip | 本轮合同：必须 `read_skill(<id>)`。列表 = 现有技能页同一目录 |
| CLI chip | 列表 = 已注册、底层是 `lark-cli` 或 `gh` 的工具名。本轮必须调用所选工具。禁止自由输入命令 |
| GitHub chip | 列表 = 看板 GitHub 页同一套未归档仓。本轮 `github_recent` / 路线图必须带上该 `owner/name` |
| 方舟 chip | 开游戏、清日常、同步森空岛、今天刷什么。点选即走现有实现，不是再写一套勾选 |
| 侧边栏 | 今日、对话、明日方舟、GitHub、飞书、日志、模型、用量 |
| 对话子界面 | 当前会话（主）、历史（按 session 列表）、记忆（喂给模型的窗口）、人设、技能 |
| 历史 vs 记忆 | 历史 = 全部 session 的全文；记忆 = 当前 session 里会按 `history_n` 喂模型的条。语义与现页一致，只改位置 |

## 4. 验收

- Given 打开看板对话，When 输入一句并发送，Then 看板出现这轮问答，并写入当前 session；气泡同步能看到。不是只追加只读列表。
- Given 当前 session 已有几句，When 点「新对话」，Then 输入区对着空线程；旧线程出现在历史子界面；`chat.jsonl` 未被整文件删除。
- Given 历史里点开旧 session，When 再发一句，Then 写进该 session，气泡也切到它。
- Given 输入区选中 `maa-log-analysis` 再问日志，When 对话，Then 本轮调用了 `read_skill` 且技能名对得上。未选 skill 时行为与现在合同相同。
- Given 选中某个已列出的 GitHub 仓再问最近提交，When 对话，Then `github_recent` 的仓库是这一个，不编未列出的仓。
- Given 输入区点「开始清日常」，When 发出，Then 走现有清日常线程（藏角色、小窗、同一份勾选），不另起勾选源。
- Given 打开看板，When 看导航，Then 记忆 / 人设 / 技能不在与「今日」平级的顶栏；它们只在对话选中时作为子界面出现。今日 / 方舟 / GitHub 在侧边栏。
- Given 今日有 CRASH 或 MAA「任务出错」，When 看侧边栏，Then 「日志」标红；点开仍是重点 + 桌宠 / MAA 分栏。

## 5. AI 失败

- 看板发送与气泡同一套：没接模型 → 去侧边栏「模型」页填；工具失败 → 原文，禁止装完成。
- 选了 skill / CLI / 仓却没调对应工具 → 本轮失败可见，不准用记忆里的旧答案顶上。
- 新 session 写盘失败 → 不静默留在旧线程；提示修 `memory/chat.jsonl`。

## 6. 最危险假设

1. 「CLI」被理解成任意命令框。验收：列表来自已注册工具，没有自由输入。
2. 「新对话」被做成清空。验收：旧 session 能从历史打开。
3. 看板对话和气泡变成两套历史。验收：同一 `session_id`。
4. 方舟 chip 复制出第二份勾选。验收：与方舟页 / 右击仍是同一份 `selected`。
