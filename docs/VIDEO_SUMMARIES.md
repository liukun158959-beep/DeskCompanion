# 视频信息与字幕总结

## 使用

左侧「看板 → 视频读取」新增独立页面。粘贴链接，点击「读取并总结」，即可查看真实任务进度、结果、字幕状态和章节，在所选记录中继续追问或保存到飞书。每个新链接使用独立会话；切换页面、断开页面连接不会停止后台任务，重新打开页面可查看结果。读取记录也包含之前在桌面对话和飞书中实际调用过视频工具的任务；普通聊天不会因为同会话读过视频而混入列表。

在知行桌面对话或飞书机器人私聊发送一个 Bilibili / YouTube 视频链接，例如「总结这个视频：链接」。仅发送链接也会按视频总结处理。支持 YouTube watch、youtu.be、shorts、live、embed，Bilibili BV/av、分 P（`?p=2`）与 b23.tv 分享链接。当前不处理播放列表、频道、番剧和批量下载。

有平台字幕时，Agent 根据实际字幕整理中文观点、细节和带时间链接的章节；英文标题按提示词要求附中文译名。支持同会话追问，例如「03:20 这一段的实现步骤是什么」。首次读取后将来源保存在本机会话目录，追问可重新核对原文。

没有字幕、需要登录或字幕读取失败时，会明确说明原因，只能整理已获取的标题、简介和平台章节，不会声称已看完整视频。自动字幕可能有误。过长字幕会分页，超出本地上限时标记截断；模型未读完时必须说明覆盖范围。第一阶段不下载音视频、不提取画面、不做音频转写。

## 网络与登录设置

左侧「视频读取 → 视频读取设置」：

平台登录入口位于独立视频页的「平台登录与视频浏览」。点击 Bilibili 或 YouTube 的「登录 / 扫码」，进入平台官方账号页（Bilibili 使用 `passport.bilibili.com/login`），在官方页面自行扫码或登录，保持窗口打开，回到知行点击「使用此登录态」。再点击「查看视频」打开输入链接；无对应链接时打开平台首页。各平台使用独立的本机 WebView2 数据目录，登录通常可跨重启保留。

B 站短信验证卡在「验证成功请稍后」时，可再次点击「登录 / 扫码」重新打开官方账号页，或者在该页使用手机 App 扫码。重新打开页面保留原登录数据，不等同于「清除登录态」。平台认证弹窗保留 `window.opener` 与相同浏览配置，避免把认证回调改成原窗口的直接跳转；极验验证域只允许验证页面导航，不收集其 Cookie，也不能调用本地助手接口。

经用户确认后的登录快照使用 Windows 当前用户 DPAPI 加密保存在 `memory/video_login/`，供视频页、桌面对话、飞书任务的同一提取器复用；不送给模型或飞书，不读取外部浏览器数据库。界面仅显示保存时间与状态，保存成功不等于平台已经验证可读；过期或平台拒绝后重新登录、更新快照。更新/清除快照自动使字幕来源缓存失效。点击「清除登录态」同时清除该平台专用窗口的浏览数据和读取快照。

登录窗口新建时沿用已经保存的视频代理设置。修改代理后先关闭该平台窗口，再重新打开。YouTube 可能拒绝内嵌浏览器登录，此时使用下方自行导出的登录文件。登录并不保证解除 HTTP 412/429、地区限制等平台限制，也不能为没有字幕的视频生成实际字幕。

- **网络代理**：可选 HTTP/HTTPS 代理，例如 `http://127.0.0.1:7890`。留空沿用系统网络。只应用于视频读取，不修改模型、飞书和资讯的网络设置。
- **字幕登录文件**：可选自己导出的 Netscape 格式 `cookies.txt` 的绝对路径，填写时优先于专用窗口保存的登录快照。Bilibili 部分字幕需登录；知行不会自动读取外部浏览器登录信息。文件内容只供本机提取器使用，不发送给模型或飞书，也不随发布包分发。

保存设置后，下次读取立即生效。更新同一路径中的登录文件后，发「重新获取这个视频」刷新缓存。平台限流不能保证通过重试解决。

## 任务与飞书保存

任务使用既有独立进程队列，桌面与飞书会话隔离。视频页显示视频信息、字幕状态、平台章节和实际进度；可以停止任务，或在完成/失败后继续和重试。在视频页追问原飞书任务，只生成本地回答；需要回复原私聊时仍在聊天监控台操作。正在读取的视频子进程会随任务取消关闭，内置读取总时限为 75 秒；监控台设置的更短时限仍优先生效。

在对话里说「把这个总结保存到飞书文档」，或在视频页所选任务的「本会话视频来源」点击 **保存当前答案到飞书文档**。聊天监控台也保留来源保存按钮。文档保存在已登录飞书用户的云空间，附原视频、作者、字幕状态与当前答案；点击按钮时选择要关联的视频。不会自动发到群，也不会自动修改每日资讯知识库。

相同会话、来源和正文保存去重，重新读取来源不会清除保存回执。保存结果未知时不自动创建第二篇；先在飞书云空间核实。确认不存在后，可以勾选监控台的核实选项重试，或明确告诉 Agent「我确认没有生成文档，请重新保存到飞书」。已有成功链接不会重复创建。

## 实现与复用依据

复用 [yt-dlp](https://github.com/yt-dlp/yt-dlp#embedding-yt-dlp) 的 Python 提取器，固定 `2026.8.19`，使用 `extract_info(download=False)` 和 `skip_download=True`；匹配的 [yt-dlp-ejs](https://github.com/yt-dlp/ejs) 固定 `0.8.0`。YouTube 需要 JavaScript 挑战时使用本机 Node，不在线下载脚本。Bilibili 网页受限时仅尝试平台公开元数据接口，字幕处理仍沿用固定版本提取器。未采用整套视频总结应用，以保留知行现有模型、会话、任务和飞书能力。

也调查了 [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api)，它专注 YouTube 字幕，无法独立覆盖 Bilibili 与元数据，因此本轮未另加依赖。上游也明确记录平台 IP 限制；本机实网测试中 Bilibili 返回 HTTP 412，YouTube 元数据可读但字幕返回 HTTP 429。测试覆盖实际字幕解析、Atlas 工具循环、会话隔离、取消与硬超时、来源缓存、写入去重和结果未知后的人工核实。

设置与来源均在本机用户目录的 `memory/` 下，不入 Git，不进入公开包。视频工具返回外部数据提示，不将字幕内容作为执行指令；飞书保存还需匹配本轮用户的连续原话。
