# V25 产品冻结：今日刷什么（库存政策 + 花钱顺序）

> grill-me 修订冻结。2026-08-28。
> 否决：仅因今日开放 / 仅因活动开着就推荐。
> 策略只回答两件事：**囤多少**、**今天先花谁**。不堆第三套例外。不进 Atlas 内核求解，不把数字交给模型口算。
> 账本用确定性代码。账号**状态**可从森空岛官方数据页建成用户模型（已用本机号验证）；仓库材料不在该接口里，改由清日常时 MAA「更新数据」自动扫仓（见 `v26_maa_depot_inventory_plan.md`）。百科、抽卡规划、RAG、桌宠自写 OCR、自动改关卡、LP、Atlas 内核求解，仍不做。
> 整体顺序以主 PRD 为准：V26 仓 → 森空岛模型（V39）→ 本规划器。本文件只冻「囤多少 / 今天先花谁」，不开工到仓和森空岛模型都能读之后。

## 0. 怎么读策略（先于功能名）

问桌宠「今天刷什么」先分两条通道，再在通道内按表取第一条：

1. **代理卡通道**（常态事务，[常态事务代理卡](https://prts.wiki/w/%E5%B8%B8%E6%80%81%E4%BA%8B%E5%8A%A1%E4%BB%A3%E7%90%86%E5%8D%A1)）：剿灭耗理智 + 卡；保全**不耗理智**、只耗卡。卡不够就说去领日常任务，不拿资源本冒充。
2. **理智养成通道**：库存政策 + `spend_order`（活动 / 芯片 / 红票等）。模组**升级材料不走主题曲掉落**。

今日开放只回答「能不能动手」。`plan` 只做冲突校验：计划消耗 > 目标 → 整份失败。

件计材料目标：`cap(item) = material_caps[item] ?? type_stocks[type_of(item)] ?? material_caps["*"]`  
龙门币用 `type_stocks.lmd`。活动代币、合成玉不走件计 50。

### 0.1 库存政策（囤多少）

类型按 [PRTS 资源收集](https://prts.wiki/w/%E5%85%B3%E5%8D%A1%E4%B8%80%E8%A7%88/%E8%B5%84%E6%BA%90%E6%94%B6%E9%9B%86) 关卡族 + [分类:材料](https://prts.wiki/w/%E5%88%86%E7%B1%BB:%E6%9D%90%E6%96%99)。消耗单位来自 [新人入门](https://prts.wiki/w/%E6%96%B0%E4%BA%BA%E5%85%A5%E9%97%A8)：精一用芯片、精二四星用芯片组、五六星精二用双芯片（2 芯片组 + 1 助剂，加工站）。芯片具体个数随星级变化，**六星精一为 5 芯片**——用这个当默认囤货单位，不是「全账号只精一一次」。

缺省 `type_stocks`：

| 类型 id | 默认目标 | 含义 | 改法 |
|---------|----------|------|------|
| `chip` | **5** | 每种职业「芯片」囤到 5（覆盖一次六星精一） | 同职业要精一多人：改 `material_caps["近卫芯片"]=10` |
| `chip_pack` | **8** | 每种职业「芯片组」囤到 8。一次五/六星精二只消耗 2 组（合成 1 个双芯片），8 组约等于同职业 4 次精二的囤货 | 同上，改具体芯片组名 |
| `skill_book` | 50 | 技巧概要·卷1/2/3 | |
| `elite` | 50 | 只囤 T2 绿 / T3 蓝；T4/T5 不刷关，走加工站 | |
| `exp` | 50 | 作战记录 | |
| `red_cert` | 50 | 采购凭证底仓。红票商店**信物**另见 `red_shop.want` | |
| `carbon` | **0** | 碳 / 碳素 / 碳素组 / 家具零件。基建要刷：改成正数 | |
| `lmd` | 2000000 | 龙门币保底，关卡 CE-6 | |

`module` **不再**表示「去日常关刷模组块」。[模组数据块](https://prts.wiki/w/%E6%A8%A1%E7%BB%84%E6%95%B0%E6%8D%AE%E5%9D%97) 来源是教学、任务、活动、采购中心（红票 120 / 黄票），不是资源收集。模组**升级**用的数据增补条 / 数据增补仪走 **保全派驻**（§0.2）。仓库里的数据块仍可用 `material_caps["模组数据块"]` 管囤货；默认不设 50 去刷关。

不刷、不设日常目标：双芯片（加工）、芯片助剂（红票店买）。基建要碳就把 `carbon` 改成 >0，不要新手开关。

### 0.2 代理卡通道（最高：剿灭；模组升级走保全，不是日常关）

定数写死自 PRTS，禁止模型改消耗或周期。

| 事务 | 消耗（PRTS） | 刷新 | 打满的条件 | 产出 |
|------|--------------|------|------------|------|
| **剿灭作战** | **1** 张代理卡 + 理智 | **每周一**额度重置（本周剿灭合成玉上限，历练后 1200～1800，见 [任务列表](https://prts.wiki/w/%E4%BB%BB%E5%8A%A1%E5%88%97%E8%A1%A8) / [新人入门](https://prts.wiki/w/%E6%96%B0%E4%BA%BA%E5%85%A5%E9%97%A8)） | `annihilation_orundum_this_week < annihilation_weekly_cap` 且卡 ≥1 | 合成玉（抽卡资源）、作战记录 |
| **保全派驻** | **2** 张代理卡，**不耗理智** | **奖励周期 = 1 个月**，每月 **16 日 04:00** 刷新（[保全派驻](https://prts.wiki/w/%E4%BF%9D%E5%85%A8%E6%B4%BE%E9%A9%BB)）。期内入库上限：增补条 60、增补仪 24。另有「派驻周期」= 4 个奖励周期（约 4 个月）才换地图/重置周期清理记录，**不要把 4 个月当成每月额度** | 本月入库未达 60/24 且卡 ≥2 | 数据增补条、数据增补仪（模组升级）。模组数据块主要不在这里刷 |

代理卡来自日常任务；每张在「领到后的下下个周一 03:59」过期，系统先扣最早过期的。

输出规则：

1. **剿灭优先级最高**（压过活动关和全部资源本）。本周合成玉额度未满 → 今天先剿灭，直到额度满或卡/理智不够。额度已满 → 本周不再推荐剿灭。
2. 保全与剿灭抢的是**卡**不是理智。剿灭扣完卡之后，若还剩 ≥2 张且本月增补未满 → **同一条建议里附带**去保全（不另占理智通道）。
3. 卡不够：写明差几张、去打日常任务；不改去刷 CA/PR 充数。
4. 快照缺本周已获合成玉、本周上限、本月已入增补、或代理卡键 → 这条通道失败可见 + 样例，养成通道仍可出。

PRTS 写剿灭全权委托是 **1 张**卡，保全是 **2 张**。不按「两边都是 2 张」口算。

### 0.3 理智养成顺序（剿灭之后）

缺省 `spend_order`（可整表重排，不可自造 id）。模型不得重排。剿灭不进此表（已在 §0.2 钉死最高）。

| 序 | id | 何时入选 | 入选后打什么 |
|----|----|----------|--------------|
| 1 | `event_shop` | 限时 SS/故事集商店未兑完，且今日活动关可打 | 代币期望最高的今日活动关（或钉死的关） |
| 2 | `event_drops` | `least_owned` 且存在「今日活动关能掉、未达目标」的件计材料 | 掉「当前最少那件」期望最高的今日活动关 |
| 3 | `chip` | 任一职业芯片 < 5 或芯片组 < 8，且今日对应 PR 开 | 未达目标里库存最少的那种；芯片组走 PR-*-2，芯片走 PR-*-1 |
| 4 | `skill_book` | 技巧概要未达目标，且今日 CA 开 | CA-5（或今日最高级 CA） |
| 5 | `red_cert` | 采购凭证 < 目标（底仓 50 与 `red_shop.want` 兑完所需取 max），且今日 AP 开 | AP-5 |
| 6 | `elite` | T2/T3 未达目标 | 企鹅对该材料期望最高的**今日可打**主题曲/插曲关 |
| 7 | `exp` | 作战记录未达目标 | LS-6 |
| 8 | `carbon` | `type_stocks.carbon > 0` 且未达目标，且今日 SK 开 | SK-5 |
| 9 | `lmd` | 龙门币 < 200 万，且今日 CE 开 | CE-6 |

全表走完没有入选项 → 今天养成可以不刷；若代理卡通道也空，报未达目标材料的下次开放日。

红票信物：[新人入门·采购凭证](https://prts.wiki/w/%E6%96%B0%E4%BA%BA%E5%85%A5%E9%97%A8) 写明红票店卖合同、**信物**、芯片助剂、六星通用信物。`red_shop.want` 点名要换的项；单价走 PRTS 采购中心，抽不出 → 失败可见。`want` 为空则只按凭证底仓 50。

活动商店：`event_shop.mode=gap` 时，想换数量 = `min(商店库存, max(0, cap − 库存))`，只对养成件计；家具/时装/活动干员信物不进 gap（写 `want`）。无限池填到 cap 为止。

### 0.4 为什么加通道、不加求解器

库存政策 + 养成顺序仍是两张表。剿灭/保全是第三条**账本**（周期额度 + 代理卡），因为机制与资源本不同：卡有过期、保全不耗理智、额度按周/月重置。不为此上 LP，也不把保全误写成「日常关刷模组块」。

桌宠只输出该打哪关、几次、该换什么。不改 MAA 关卡，不假装仓库已变。

### 0.5 用户模型（森空岛状态 + 本地策略，不是人格画像）

`player/info` 已能建成一份**账号状态模型**，给规划当输入，不拿去猜「博士想练谁」、不写进 Atlas RSI。

**从森空岛填（刷新即覆盖，禁止模型改数）：**

| 模型块 | 字段 | 来源 |
|--------|------|------|
| 身份 | uid、等级、主线进度、上次在线 | `status` |
| 今日体力 | **实时理智**（不得直接用 `ap.current`） | 见下 |
| 月卡 | `subscriptionEnd` > 现在 → `monthly_card=true` | `status.subscriptionEnd` |
| 周期额度 | 本周剿灭玉 current/total；本月增补仪/条 current/total、termTs | `campaign.reward`、`tower.reward` |
| 干员箱 | 每位 `evolvePhase`、`level`、技能等级、专精、模组 | `chars[]` → 填 `plan[].current` |
| 进度旁路 | 剿灭各图最高击杀、保全记录、活动关 zone 进度 | 第一刀规划可不用 |

实时理智：`ap.current` 是上次结算快照。`completeRecoveryTime` 为 -1/0 时界面理智 = `current`（可高于 max）；`currentTs >= completeRecoveryTime` 时 = `max`；否则 `min(max, current + floor((currentTs - lastApAddTime) / 360))`（6 分钟 1 点）。已用本机号验证：裸 `current=15`、算完 = 210。

**仍在本地、森空岛没有：** `inventory`（材料/龙门币/代理卡/药）、`strategy`（囤多少、花钱顺序、want）。缺仓库就失败可见，不把干员箱假装成仓库。

**怎么用：** 规划读「用户模型 ∩ 策略表」。剿灭/保全额度、当前精二进度、今天还剩多少理智走模型；芯片该囤 5 还是 10、碳刷不刷、信物 want 走策略。目标干员仍要用户写 `plan.target`（或之后另开「我想练谁」），接口不会告诉你目标。

不把 427 名干员全文塞进 LLM 上下文。规划器只取：实时理智、周期额度、以及 `plan` 点名的干员当前值。

## 1. 问题

**When** 博士今天有理智和代理卡，本周剿灭玉可能还没打满，仓库按「每种囤到几」管  
**I want** 先知道剿灭/保全还要不要做，再知道养成关值不值得打  
**so I can** 周玉和月增补不漏，芯片停在 5/8，碳默认不刷，而不是拿日常关去刷模组块

现在的凑合：自己记「先剿灭、保全每月 16 号刷新、芯片别囤太多」。只推「今天开了什么」比这个更差。把模组当普通掉落关、剿灭不当最高优先——已否决。

## 2. 账本四则（禁止模型口算）

缺能算的数就失败或降级，不编。

1. **目标与计划**：`cap` 按 §0.1。`plan` 选填。有 plan 时按干员查 [PRTS](https://prts.wiki/index.php?curid=1) 精英/技能/专精，引用链接；拉不到 → 该干员失败。任一消耗 > cap → 整份失败。无 plan 不失败。
2. **库存**：比较过 cap 或进了商店/掉落候选的键必须有；缺键失败，不当 0。周期额度与干员当前值优先来自用户模型（§0.5）；`event_shop` 未 off 时活动代币必须有键。`red_shop.want` 非空时采购凭证必须有键。代理卡通道还要代理卡库存（模型没有则仍要 json 键）。
3. **关卡产出与理智**：资源本理智写死；活动关 PRTS 关卡表；剿灭理智按该图最高歼灭档，写死或引自 PRTS 该剿灭页。掉落/代币走企鹅 Matrix。企鹅失败 → 养成仍给未达目标与能否刷，不编次数。
4. **理智供给**：自然回复 240/天 × 剩余天数 + 药（小 10 / 中 60 / 大 120）。月卡只加合成玉，不加自然回复。日常任务给代理卡，不把任务合成玉编进供给。

**版本日：** PRTS → 官网 → B 站，抽不出 `YYYY-MM-DD` 则留空，只按库存政策，可手填 `next_version`。禁止猜。

**代理卡账：** 消耗与周期见 §0.2。本周剩余合成玉 = `weekly_cap − orundum_this_week`。本月剩余增补 = `(60 − strip_this_period, 24 − device_this_period)`。禁止把派驻周期（4 个月）当成奖励周期（1 个月）。

**活动商店账：** `mode=off` 跳过。PRTS 限时 SS/故事集页抽活动、商店表、开关日。抽不出活动 → 商店与掉落都跳过，不猜名字。多活动重叠且未写 `event` → 失败。抽不出表或关闭日 → 商店条失败，日常政策仍可出。不算首通/任务/签到代币。

**红票商店账：** `red_shop.want` 为空则只比 `type_stocks.red_cert`。非空则 `采购凭证目标 = max(type_stocks.red_cert, want 总价 − 已有可兑进度)`。已有信物库存够 want → 该项不计价。PRTS 采购中心无该名 → 失败，给链接和样例。

**活动关掉落账：** `event_drops.mode=off` 跳过。候选 = 今日活动关掉落 ∩ 件计 ∩ 库存 < cap。空集跳过。取库存最少；关卡取该材料期望最高（可钉死，钉的关不掉则失败，不换关）。

## 3. 非目标

| 不做 | 原因 |
|------|------|
| 因今日开放 / 活动开着就推荐 | 必须未达目标 |
| 计划缺口当停刷闸门 | 闸门是库存政策 |
| 全局 50 套在芯片/碳上 | 已改为类型默认 5 / 8 / 0 |
| 新手画像、自动判断基建是否毕业 | 改 `carbon` 目标即可 |
| 搬空红票店 / 攻略站兑换顺序 | 只兑 want + 凭证底仓 |
| 抽卡规划、黄票店、危机合约店 | 另开刀。本周**剿灭合成玉额度**要打完，不是规划寻访 |
| 日常关刷模组数据块 | 数据块不在资源收集掉；升级材料走保全 |
| 百科 RAG、Atlas LP、自动改 MAA 关卡 | 同前 |
| 桌宠自写仓库 OCR / 点游戏仓库 | 复用 MAA。小工具点识别本机已验会自动进仓，但入口仍是清日常「更新数据」，人不点小工具，见 V26 |
| LLM 填掉率、单价、目标、顺序 | 失败可见 |
| 计入首通/任务代币 | 会虚高 |

## 4. Must（≤3）

1. **库存政策 + 周期额度**：件计按 §0.1；剿灭按本周剩余合成玉；保全按本月剩余 60/24。`carbon=0` 永不进 SK。缺库存或 `standing` → 失败 + 样例。plan 超过目标 → 失败。
2. **今天先做哪条**：代理卡通道里剿灭最高；有剩卡再保全。然后按 `spend_order` 取养成第一条。卡不够说领日常，不拿资源本充数。
3. **量是否够**：企鹅 + 关卡/剿灭理智 + 截止日前回复与药。日常/掉落用版本日，活动商店用关闭日，剿灭用本周一重置，保全用下个 16 日 04:00。缺数则降级，不编。

## 6. 验收

- Given 本周剿灭合成玉 0/1800、代理卡 ≥1，When 问今天刷什么，Then **先推荐剿灭**，即使活动开着、芯片未满。
