# 本周复盘（飞书 Markdown）

读者是作者自己，任务是看清这周交出了什么、还欠什么。走 `docs +create --doc-format markdown`，只写导入能保真的语法。

## 能用的语法

标题、连贯段落、列表、引用块、表格、加粗。

禁止：emoji、高亮块、分栏、画板、Mermaid、代码块包整篇、每个仓库升成一级标题。

## 结构（按这个顺序，不要加第四节以外的章节）

先写引用块，三行：

```
> **重点**
> 事项名（来源或截止）
```

没有「最该盯的一件待完成」时，第二行写「无」。

然后：

```
# 本周复盘（YYYY-MM-DD～YYYY-MM-DD）
## 产出
## 会议
## 待完成
```

- **产出**：只写材料里「GitHub 产出」的 commit / 已合并 PR / 已关闭 issue。按仓库用表或短列表。没有则写「无」。禁止把会议、待办、对话抄进产出。
- **会议**：只写材料里「飞书本周日程」。没有则写「无」。这是占用，不是产出。
- **待完成**：飞书未完成待办、未合并 PR、带 milestone 的未关 issue。多于一条用表，列：事项、来源、截止或链接。材料写明「有未关 issue、无路线图」时照抄条数，不要编成规划。没有则写「无」。

## 红线

- 材料没有的事不写。不知道截止就写「无截止」，不编完成率。
- 标题只给上面这些章节。
- 不要鸡汤，不要「持续推进」代替具体事项。
- 不要包一层 Markdown 代码块；直接输出正文。
- 达到条数上限而被截断的仓库，在产出里标明材料原句，不要假装看全了。
